## Этап 2. Анализ (done, 2026-10-06)

Что сделано:
- Распознавание речи: faster-whisper (`small`, int8, CPU) с VAD. Звук извлекается через FFmpeg. Текст, язык и сегменты сохраняются в базе. Если у ролика нет своего `.srt`, субтитры делаются из речи.
- Метрики качества по кадрам (1 кадр/с): доля чёрного, застывшей картинки, размытость, громкость и тишина. Отдельные пороги отсекают брак без вариантов.
- Единый `LLMProvider`: `llamacpp` (основной, локальная Qwen2.5-7B-Instruct Q4_K_M на Metal), `openai` (любой OpenAI-совместимый API), `rules` (запасной вариант без модели). Переключается одной строкой `ai.provider` в конфиге.
- Оценки: quality, viral, originality, source, freshness, format и итоговый балл по формуле раздела 22 ТЗ. Веса и пороги задаются в `config.yaml`.
- Права: расширенный список статусов (PUBLIC_DOMAIN, CC0, CC_BY, CC_BY_SA…) и `rights_risk_score`. Ролики с неподтверждёнными правами уходят на ручную проверку и в очередь публикации не попадают.
- Модерация. Ключевые слова могут отклонить ролик сами. Флаги, которые поставила только модель, отправляют ролик человеку: на реальных постах модель приняла шутку за «hate», а новость о смерти стримера за «nsfw».
- Категории: модель выдаёт категорию, уверенность и обоснование. Если данных мало или уверенность ниже 60%, ставится «uncertain» («не разобрался»). Категория канала служит только подсказкой. Ручная смена категории не перезаписывается.
- Ручная проверка: `review` (approve / reject / skip), ссылки на ролики лежат в `data/review/`. Решение по каждому ролику полностью записано в `analysis_json`.
- Таблица `performance` подготовлена для будущей модели ранжирования.

## Этап 3. Источники (done, 2026-10-06)

## Этап 4. Очередь и публикация (done с изменением, 2026-10-06)

Состав по решению пользователя (через координатора): публикуем только в **Instagram Reels**. YouTube Shorts и TikTok не делаются. Подписи и хэштеги **не генерируются**: у ролика есть поле «Описание», его заполняет человек. Рядом показаны 10 последних описаний из базы, клик подставляет одно из них. В ТЗ (разделы 38–39) была AI-генерация, это осознанное расхождение.

API сверено с актуальной документацией Meta (Instagram Platform → Content Publishing, Resumable Uploads, IG User Media, октябрь 2026). Используется Instagram API с Facebook Login for Business, `graph.facebook.com` v25.0:
`POST /{ig-user-id}/media` (REELS, upload_type=resumable) → `POST rupload.facebook.com/ig-api-upload/v25.0/{container}` (файл прямо с Mac, публичный URL не нужен) → `GET {container}?fields=status_code` до FINISHED → `POST /{ig-user-id}/media_publish`. Лимит Meta: 100 публикаций через API за 24 часа (`content_publishing_limit`).

Что сделано:
- Таблица `publications`: ролик, платформа, аккаунт, описание, время, статус (QUEUED, PROCESSING, PUBLISHED, FAILED, WAITING_USER, CANCELLED), попытки, ID контейнера, ID поста, ссылка, причина ошибки (HTTP, код API, request ID, время), отчёт dry-run, журнал событий. Частичный уникальный индекс: на один ролик одна действующая публикация. Таблица `app_settings` хранит переключатели из интерфейса (пауза, dry-run или реальная публикация). Секреты в базу не пишутся.
- Ручное одобрение прав обязательно. В очередь можно поставить только ролик `READY_TO_PUBLISH` с разрешающим статусом прав. `UNKNOWN`, `REQUIRES_REVIEW` и `REJECTED` сначала проходят ручную проверку, где получают `VERIFIED`. Плюс у каждой публикации нужна отдельная отметка человека «права проверил». Перед отправкой права проверяются ещё раз: если их отозвали, публикация уходит в WAITING_USER.
- Проверка формата Reels перед отправкой по требованиям Meta (настраивается в `config.yaml`): MP4 или MOV, H.264 или HEVC, AAC до 48 кГц и 2 каналов, 23–60 кадров/с, ширина до 1920, 9:16, от 3 с до 15 мин, до 300 МБ, до 25 Мбит/с, moov в начале файла. Звук в новых роликах кодируется в 128 кбит/с, как в требованиях Reels (было 192).
- Повторы без дублей. ID контейнера сохраняется сразу после создания. Повтор и восстановление после сбоя сначала проверяют контейнер: PUBLISHED → пост ищется среди последних и записывается, второй раз не публикуется; FINISHED → только `media_publish`; оборванная загрузка докачивается с `bytes_transferred`; ERROR или EXPIRED → создаётся новый контейнер. Временные ошибки повторяются через 5 и 15 минут, после 3 попыток статус WAITING_USER. Ошибки токена (190) и разрешений (10, 2xx) сразу WAITING_USER, без повторов. При лимите Meta отправка откладывается на час, попытка не засчитывается.
- Дневной лимит (5, сутки по Europe/Moscow), пауза между публикациями (60 минут), время «не раньше», общая пауза. Для каждого ролика в очереди считается время отправки.
- Планировщик в фоновом воркере веб-сервера: раз в 30 с отправляет не больше одного ролика. В режиме dry-run он записывает план проверки и ничего не отправляет.
- Подключение: «Проверить подключение» (токен, разрешения `instagram_basic`, `instagram_content_publish` и `pages_read_engagement`, аккаунт, доступность публикации, срок токена), «Найти» аккаунт по страницам Facebook, сохранение токена и ID в `.env` (права 600, токен потом не показывается), «Обновить токен» через `fb_exchange_token`. Автообновление, когда до конца срока меньше 10 дней (нужны `META_APP_ID` и `META_APP_SECRET`).
- Веб-интерфейс, раздел «Публикация»: плитки лимитов, «Готово к публикации», диалог постановки в очередь (видео, описание с последними вариантами, время, чек-лист, подтверждение прав), очередь с вкладками и кнопками, карточка подключения, переключатель dry-run или реальная публикация, пауза. В «Роликах» появилось поле «Описание для Instagram».
- CLI: `publish --dry-run` (что, куда, когда, описание, проверки; база только для чтения), `publish`, `instagram check`, `instagram refresh-token`. В `health` есть строка Instagram.
- Инструкция по Meta: `docs/instagram.md`.
- 20 новых тестов на имитации Graph API (`tests/test_publishing.py`), всего 93 теста, все зелёные.

### Изменение этапа 4: ручная публикация (2026-10-06)

Пользователь не может создать приложение Meta, поэтому автопубликации в Instagram не будет. Ролики выкладываются вручную. Этап 4 закрыт с этим изменением, пункт про реальную публикацию через API снят.

- Коннектор Instagram Graph API и очередь остаются в коде и тестах, но выключены (`publishing.enabled: false`, `publishing.instagram.enabled: false`) и убраны из меню. Адрес `/publish` перенаправляет на «Готовые видео». Планировщик ничего не отправляет.

## Этап 7. Редактор (in progress, 2026-10-06)

Устройство: у каждого ролика есть спецификация монтажа (JSON, таблица `edit_projects`), из неё один запуск FFmpeg строит ролик прямо из исходника. Превью в браузере (кадр или короткий ролик 540×960) строится **тем же графом фильтров** с уменьшением в конце, поэтому превью совпадает с экспортом. Слои: фон → баннер «под» → тень → ролик → обводка → баннер «над» → тексты → субтитры. Тексты, маски, тень, обводка и градиент рисуются Pillow, потому что в FFmpeg из Homebrew нет drawtext и libass.

Сделано (7a и часть 7b/7c):
- Фон: размытие самого ролика, цвет, градиент, своя картинка или видео.
- Окно видео: положение и размер (перетаскивание на холсте и поля), «целиком» / «заполнить», зум, форма (прямоугольник, скругления, круг), обводка, тень. Пресеты: весь экран, квадрат, 16:9, «мем: белая рамка с подписью».
- Баннер (картинка или видео) над роликом (рамка) или под ним, положение и масштаб. **Хромакей**: при загрузке зелёный или синий фон определяется автоматически и убирается (`colorkey`), цвет, допуск и мягкость края можно поправить вручную.
